# 中继网络与请求边界升级记录

日期：2026-09-05

## 目标与范围

本次变更收紧两类中继边界：为等待上游响应头增加可配置超时，并使客户端请求解析
失败在进入上游转发前稳定返回不可重试的客户端错误。同时，对访问令牌生成和返利额度
转账复用已有的认证用户限流器。

## 配置契约

`RELAY_RESPONSE_HEADER_TIMEOUT` 的单位为秒，默认值为 `1800`：

- 正整数限制请求体上传完成后等待上游响应头的时间；
- `0` 禁用该限制；
- 负数按禁用处理；
- 超出 `time.Duration` 可表示范围的值会在换算前截断，避免整数溢出后形成意外的极短超时。

该超时应用于普通直连、环境 HTTP 代理、渠道 HTTP/SOCKS 代理、带 SSRF 校验的抓取
客户端，以及 Claude Code 指纹传输的直连和代理路径。它不限制 DNS、建连、请求体上传
或响应头返回后的流式读取。现有 `RELAY_TIMEOUT` 仍是覆盖整个请求生命周期的独立设置。

## API 与安全边界

- 中继 JSON、表单或 multipart 请求无法解析或校验时返回 HTTP `400`，并设置
  `SkipRetry`，不会选择或请求上游渠道；
- 解压后请求体超过 `MAX_REQUEST_BODY_MB` 时继续返回 HTTP `413`，同样不重试；
- `/api/user/token` 和 `/api/user/aff_transfer` 在 `UserAuth` 之后按用户 ID 限流；
- 两个操作使用独立计数桶，同一出口 IP 下的不同用户互不占用额度；
- 代理选择、TLS 配置、Claude Code TLS 指纹和 SSRF 地址校验逻辑不变。

## 兼容性与回滚

默认响应头等待上限可能使此前无限等待的失联上游请求在 30 分钟后失败。需要保留旧行为
时可设置 `RELAY_RESPONSE_HEADER_TIMEOUT=0`。代码不包含数据库迁移，也不修改渠道、余额
或计费数据。回滚应用镜像即可恢复旧行为；配置项可保留，旧版本会忽略它。

## 验证计划

GitHub Actions 运行以下回归：

- 超时换算覆盖默认值、禁用、负数和溢出截断；
- 普通直连、HTTP/SOCKS 代理、SSRF 客户端及 Claude 自定义传输均携带相同响应头超时；
- 延迟响应头触发超时，快速响应头后的慢响应体仍能完整读取；
- 非法请求返回不可重试的 `400`，超大请求体保持不可重试的 `413`；
- Rerank 和 Embedding 的 `null`、数组或标量请求体在访问请求字段前拒绝，不因空指针返回 `500`；
- 用户限流隔离用户和操作，并沿用 `429` 拒绝响应。

限流回归使用唯一操作桶，不替换共享内存限流器，避免与已有清理协程竞争。

本地仅执行静态差异检查；`gofmt`、Go 编译和测试由 GitHub Actions 执行，不在生产
VPS 或本地工作区运行。
